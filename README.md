# Palworld Control Center

PCC is a terminal-first Palworld server installer and operations panel for Linux. The installer, configuration handling, backups, restore workflow, SteamCMD updates and system integration are implemented in Rust; no Bash AIO runtime is installed.

## Installation

PCC intentionally has one setup command. Download both release assets, verify the binary and install the panel system-wide:

```bash
sha256sum --check palworld-control-center-linux-amd64.sha256
chmod +x palworld-control-center-linux-amd64
sudo ./palworld-control-center-linux-amd64 install
```

Then use the short command:

```bash
sudo pcc
```

On the first normal start, PCC notices that no managed Palworld server exists and opens the native installation wizard automatically. It installs SteamCMD and Palworld, creates the isolated `palworld` service account, enables the REST API, configures systemd services and timers, and optionally applies UFW rules. Later calls open the dashboard directly.

Supported production hosts are Debian 13 and Ubuntu Server 26.04 LTS on amd64 with systemd. An existing world is never silently overwritten. Back it up and intentionally remove or migrate the old installation before requesting a clean install.

## Daily operation

The dashboard is read-only by default:

```bash
sudo pcc
```

Enable confirmed mutations for one session:

```bash
sudo pcc --enable-writes
```

There are no user-facing server, backup, update or configuration subcommands. Those operations live in the dashboard. `pcc install` is the only setup subcommand; systemd uses a hidden internal task interface generated by PCC itself.

Common controls:

- `←` / `→` or `h` / `l`: change tabs
- `↑` / `↓` or `j` / `k`: select an item
- `1`–`8`: open a tab directly
- `r`: refresh
- `q` or `Ctrl+C`: exit

For a preview without an installation:

```bash
pcc --demo
```

## Automatic PCC updates

A system-wide installation enables `palworld-control-center-update.timer`, which checks GitHub releases daily. Alpha installations use the `prerelease` update channel by default so newer PCC alpha releases can be installed automatically.

Inspect the updater with:

```bash
systemctl status palworld-control-center-update.timer
systemctl list-timers palworld-control-center-update.timer
```

Trigger an immediate update check with:

```bash
sudo systemctl start palworld-control-center-update.service
journalctl -u palworld-control-center-update.service -n 100 --no-pager
pcc --version
```

The selected channel is stored in `/etc/palworld-control-center/update-channel`. Supported values are `prerelease` and `stable`.

The self-updater accepts only semantic release tags from this repository, downloads the fixed amd64 binary and checksum over HTTPS, verifies SHA-256, validates the ELF architecture, marks the temporary binary executable only after those checks, verifies the reported version, and atomically replaces the installed executable.

## Managed layout

| Purpose | Path |
| --- | --- |
| PCC binary | `/usr/local/bin/palworld-control-center` |
| Short command | `/usr/local/bin/pcc` |
| Native server config | `/etc/palworld-control-center/server.json` |
| Protected REST credentials | `/etc/palworld-control-center/rest.netrc` |
| Palworld and SteamCMD | `/opt/palworld` |
| Backups | `/var/backups/palworld` |
| Runtime state | `/var/lib/palworld-control-center` |

PCC installs daily self-update checks plus Palworld backup and update timers.

## Features

- Overview with service/API state, host resources, version, players, FPS and live journald logs.
- Player actions through the protected local Palworld REST API.
- Searchable `PalWorldSettings.ini` editor that preserves unknown and nested options and never renders secrets.
- SHA-256 backups, verification and transactional world restore with a pre-restore backup and rollback.
- Backup-first SteamCMD updates from systemd or the dashboard.
- Security checks for credentials, installation, updater, backup directory and REST firewall boundary.
- Redacted local diagnostics and a privacy-reduced optional DynaCat Unix-socket API.

Experimental native Linux PAK discovery is visible, but mutation remains disabled until the Rust package manager is complete. Pocketpair currently documents native PAK loading as experimental.

## Security baseline

- REST credentials are generated locally and stored as root-owned mode `0640` files.
- PCC contacts Palworld only through `127.0.0.1`; the installer can configure UFW to reject external REST traffic.
- Child processes use fixed executables and separate arguments; there is no free-form shell evaluation.
- Every mutation requires `--enable-writes`, a confirmation screen and an authpriv audit event.
- Backup paths reject symlinks and paths outside the configured backup root.
- Restore archives are checksum-verified and inspected before extraction.
- Player IP addresses and full identifiers are excluded from the normal TUI and DynaCat API.

Legacy `/etc/palworld/palworld.env` installations can still be inspected during migration, but new installations use only the Rust-managed layout above.
